# 微信状态图片表情设计

日期：2026-07-27

## 目标

为 OpenCode 微信通知增加微信原生图片表情，使用户能快速识别任务完成、错误、审批和超时等状态。

## 实现方式

插件继续通过现有文本消息 API 发送单条通知，在通知文本开头加入微信内置表情快捷码。微信客户端会把 `[表情名]` 转换为对应的原生图片表情，不需要下载、打包或上传图片文件。

示例：

```text
[庆祝] 任务完成
New session - 2026-07-27T05:03:05.697Z
```

## 状态映射

| 状态 | 微信快捷码 | 使用场景 |
| --- | --- | --- |
| 完成 | `[庆祝]` | `session.idle` |
| 错误 | `[苦涩]` | `session.error` |
| 等待审批 | `[让我看看]` | `permission.ask` |
| 批准 | `[好的]` | 审批结果为 `once` 或 `always` |
| 拒绝 | `[NO]` | 审批结果为 `reject` |
| 超时 | `[叹气]` | 审批超时自动拒绝 |
| 警告 | `[汗]` | 审批码过期等警告 |
| 帮助 | `[机智]` | `help` 命令响应 |

## 代码结构

新增一个无状态的消息格式化模块，集中维护状态类型、微信快捷码映射和前缀函数。业务代码只传入状态与正文，不直接散落表情字符串。

格式化接口：

```ts
formatStatusMessage(status, message)
```

输出格式固定为：

```text
[微信表情快捷码] 正文
```

已有英文状态标签可以保留在正文中，以兼容日志搜索和现有使用习惯。

## 兼容与降级

- 支持微信快捷码的客户端会显示原生图片表情。
- 未转换快捷码的客户端仍能看到可读的 `[表情名]` 文本。
- 不改变 ilink API、消息类型或凭据格式。
- 不增加外部图片资源、网络请求或运行时依赖。

## 测试

单元测试覆盖：

1. 每个状态对应正确的微信快捷码。
2. 格式化结果只生成一条消息。
3. 未知状态使用警告表情降级。
4. 现有通知正文和审批编号保持不变。

构建、单元测试和敏感信息扫描通过后，同步当前本地插件并推送 GitHub。
